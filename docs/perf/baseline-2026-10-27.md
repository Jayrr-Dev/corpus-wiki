# Route speed baseline (2026-10-27, `next dev`, signed in)

Measured in the browser pane against `next dev` on port 3001 with
`docs/perf/measure-routes.js`. Dev numbers are noisy (first visits compile);
compare request counts and waterfalls more than milliseconds.

## Server response (HTML fetch, second pass)

Every signed-in page takes about 0.6 to 1.0 s before any HTML comes back.
The public `/explore` takes 0.25 to 0.4 s. So about 0.4 s is spent per request
in the proxy and `app/(app)/layout.tsx` (auth claims, a space lookup in the
proxy, `ensure_my_space` RPC, a spaces list), one after another.
`/settings` returns 523 KB of HTML and takes 1.4 s.

## Shared cost on every signed-in page

`/ask` and `/workflow` have about 13 fetches, which is the shell alone:
sidebar badges and tree (`exceptions`, every `sources` row, every upload
`shift_events` row, `read_upload_workflows`, `pages`, `domains`, `entities`,
suggestion counts). The sidebar loads whole tables to compute badges.

## 431 Request Header Fields Too Large

The pane's cookie for localhost is 2.5 KB, so the app's own cookies are not the
cause. Browsers share localhost cookies across ports, so other local apps
(other ports) add theirs to every request; Node rejects headers over 16 KB
before Next sees the request (nothing in the dev log). Fix: clear localhost
cookies in that browser, or open the app at 127.0.0.1.
