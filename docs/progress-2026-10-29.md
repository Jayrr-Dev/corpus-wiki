## Hybrid chat search with Voyage rerank

**What it does.** `rankUnits` (`lib/chatbot/rank.ts`) runs several searches:
meaning, keyword, links, and meaning and words inside a chosen entity. It fuses
the capped lists with reciprocal rank fusion, then Voyage `rerank-2.5` re-sorts
the top 40. If the rerank call fails, the answer uses the legacy order.

**Before.** Legacy search by default. Hybrid needed `CHAT_SEARCH=hybrid`, and
the reranker needed `CHAT_RERANKER=voyage` plus `VOYAGE_API_KEY`. PR #54 made
hybrid fall back to legacy when no reranker is configured.

**Measured** (60 questions, `evals/retrieval`):

| Mode | hit@5 | hit@10 | MRR | Median time | Measured |
|---|---|---|---|---|---|
| legacy | 90.0% | 96.7% | 0.804 | 257 ms | 2026-10-26 and 2026-10-29 (same) |
| hybrid, no reranker | 53.3% / 58.3% | 73.3% / 75.0% | 0.477 / 0.488 | 405 / 434 ms | 2026-10-26 / 2026-10-29 |
| hybrid + Voyage | 98.3% / 100% | 98.3% / 100% | 0.902 / 0.908 | 796 / 823 ms | 2026-10-26 / 2026-10-29 |

A reranked search uses about 1,980 Voyage tokens, about $0.10 per 1,000
searches at list price. It adds about half a second per question.

**After.** Chat search is hybrid plus Voyage rerank whenever `VOYAGE_API_KEY`
is set, and legacy otherwise. Hybrid never runs without the reranker, because
alone it ranks worse than legacy. `CHAT_SEARCH` and `CHAT_RERANKER` are gone;
the key is the only switch. Deleting the key turns the rerank, and so hybrid,
off.

**In production** since 2026-10-29.

## Slimmer topic prompts (`TOPIC_PROMPT_BUDGET`)

**What it does.** Topic placement gives each batch only the saved claims its
own candidates and links name, points profile examples at them instead of
copying their text, and halves any plan step or batch whose prompt would pass
100k tokens (`lib/domains/promptBudget.ts`, used by
`lib/ingest/placeTopicsServer.ts`).

**Before.** Off unless `TOPIC_PROMPT_BUDGET=on`.

**Measured** (2026-10-26, real uploads): topic prompts 8 to 38% smaller, with
the same placements. Over 30 days, 265 calls went past Haiku's 100k-token line
and cost $22.52 (25% of all AI spend), mostly `place_topics` and
`independent_upload_domain_review`. The 3 days to 2026-10-29 had no call over
100k tokens, but also no large upload, so the switch has not yet been tested
against a big book in production.

**After.** On by default. `TOPIC_PROMPT_BUDGET=off` still restores the original
prompts. #43 asks for one week in production without placement regressions
before the switch is settled, so the off switch stays until about 2026-11-05.
Then the off branch in `placeTopicsServer.ts` can be removed.

**In production** since 2026-10-29.

## NLI prefilter in duplicate checks

**What it does.** `lib/dedup/prefilter.ts` uses a free local NLI model to drop
duplicate-check candidates that are clearly unrelated, before the AI call.

**Before and after.** Unchanged. It is built and on by default (`DEDUP_NLI=off`
turns it off), but no duplicate check calls it yet, so it saves nothing. Wiring
it into the glossary and claims checks is a follow-up, not part of #43's PR.
