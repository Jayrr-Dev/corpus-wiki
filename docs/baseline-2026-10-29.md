# Phase 0 baseline, 2026-10-29

The numbers every later PR in #55 must meet. Taken on `main` at `62998b5`.
Raw results sit next to each tool; this page only summarizes them.

## Summary

- **Cost:** $89.83 over 30 days (2026-09-29 to 2026-10-29), against $87.90 in the
  2026-10-26 baseline. The two windows share 27 days, so the new baseline adds
  little: the 3 new days cost $1.93, three quarters of it glossary duplicate review.
- **Time (synthetic, no AI):** short document 2.8 s, long document 10.6 s,
  update of existing pages 3.6 s. Writing pages is 70% of the time; reconcile
  is most of the rest.
- **Retrieval on main:** legacy hit@5 90.0%, hybrid 58.3%, hybrid + Voyage
  rerank 100%.
- **PR #52 (#38) brings no gain and regresses the fallback.** Hybrid + rerank,
  which production uses since #43's env vars were set on 2026-10-29, is
  unchanged. Legacy, used whenever no reranker is configured, drops from hit@5
  90.0% to 85.0% and MRR 0.804 to 0.722. Do not merge it as is.
- **`evals/evals.test.ts` fails as is (7 of 7), from a stale test helper.**
  `test/db/pgRpc.ts` sends arrays as JSON text, and `read_upload_workflows`
  takes `uuid[]`. With typed arguments (as `test/db/portablePostgres.ts` does)
  all 7 pass, and `evals/live.test.ts` passes in 31 s on one small file. Run in
  a Linux container; see section 3.

How to read it:

  $11.41) are still inside the window and still dominate.
- **Largest purposes** are unchanged from the old baseline:
  `independent_upload_domain_review` $9.95, `place_topics` $9.45,
  `page_editorial_review` $7.76, `independent_section_editorial_review` $7.73,
  `article_outline` $6.99, `line_fact_check` $6.69. Only
  `glossary_duplicate_review` grew ($4.59 to $6.06) and `reconciliation`

- **By role:** reviewer $39.10 (43.5%), domain decider $21.27 (23.7%),
  plan articles $8.82, composer $6.96, dictionary editor $5.88.
- **By model:** Sonnet 5.5 $43.31, Haiku 5.5 $34.25, Opus 5.5 $8.91.

The 3 new days alone (2026-10-26 to 10-29, same command with those dates): $1.93
over 966 calls, 99.9% Haiku, no call over 100k tokens. `glossary_duplicate_review`
was $1.47 of it (425 calls), almost all not tied to an upload, so it ran after
the uploads it served. The 15 uploads in those days cost $0.0117 each.

## 2. Time

`pnpm test:synthetic` passes (13 files, 123 tests). It hides console output, so
the per-stage numbers come from running its upload file with logs on (same env):

```bash
PROCESSING_BENCHMARK=1 PROCESSING_SYNTHETIC=1 npx vitest run test/performance/syntheticUpload.test.ts --silent=false
```

Each stage logs "Upload stage timing" (`lib/ingest/workflow.ts`). Three runs;
medians below, all three in `scripts/performance/results/2026-10-29-synthetic.json`.
The test uses an in-process PGlite Postgres with the full migration chain, and
deterministic stand-ins for extraction and section prose, so there are no AI
calls. Stages with nothing wired in the test (duplicates, tidy, place,
hierarchy, expand, embeddings, describe, profiles, glossary, curate) take 0 ms
and are left out. Other lanes were running tests on the same machine, so the
runs are noisy (the long document took 6.3 to 12.6 s).

| Scenario | Claims | Whole run | reconcile | plan | pages | articles-ready |
|---|---|---|---|---|---|---|
| Short document (8 entities) | 72 | 2,815 ms | 602 ms | 88 ms | 1,935 ms | 14 ms |
| Long document (16 entities) | 192 | 10,645 ms | 1,976 ms | 143 ms | 7,414 ms | 13 ms |
| Update to existing pages | 24 new (96 total on the pages) | 3,600 ms | 856 ms | 30 ms | 2,529 ms | 14 ms |

What it shows: the update writes 24 claims but takes longer than the short
document that wrote 72. Its reconcile (856 ms vs 602 ms) and pages
(2,529 ms vs 1,935 ms) grow with what is already stored, not with the upload.
That is the problem #45 and #46 target. The repeated run on a finished upload
takes about 15 ms (checkpoints only).

## 3. Quality

### Retrieval (`evals/retrieval`, main)

Read-only against the live database; questions embedded on Nebius
(Qwen3-Embedding-8B), reranked by Voyage `rerank-2.5`. 60 questions (10 scoped
to an entity, 50 not). All runs valid (no warnings, failures or unreranked
questions). Files: `evals/retrieval/results/2026-10-29-main-*.json`.

| Variant | hit@5 | hit@10 | MRR | Scoped MRR | Unscoped MRR | Median per question |
|---|---|---|---|---|---|---|
| legacy | 90.0% | 96.7% | 0.804 | 0.775 | 0.810 | 259 ms |
| hybrid | 58.3% | 75.0% | 0.488 | 0.357 | 0.514 | 434 ms |
| hybrid + rerank | 100.0% | 100.0% | 0.908 | 0.900 | 0.909 | 823 ms |

Against 2026-10-26: legacy is identical; hybrid 53.3% to 58.3% hit@5; hybrid +
rerank 98.3% to 100% hit@5. A repeat run of legacy and hybrid on main gave the
same totals (58 of 60 questions at the same rank), so run-to-run noise is small.

### Extraction and pipeline evals (`evals/`)

These need Postgres 16 at `/usr/lib/postgresql/16/bin` (`test/db/localPostgres.ts`),
so they ran in a Linux container: `postgres:16-bookworm` with
`postgresql-16-pgvector` and Node 22 copied in, the repo mounted, packages
installed inside. On Windows they skip.

- `evals/fixtures.test.ts`: 28 passed.
- `evals/evals.test.ts` (E1 to E7) **as is: 7 failed**, all with
  `malformed array literal: "["<uuid>"]"` from `read_upload_workflows`
  (`readResult` in `lib/ingest/workflow.ts`). `test/db/pgRpc.ts` turns every
  array into JSON text, which only fits `jsonb` parameters, and returns only the
  first row of SETOF functions. `evals/results/2026-10-29-evals-as-is.json`.
- `evals/evals.test.ts` **with typed arguments: 7 passed.** For this run only,
  `pgRpc.ts` looked up each argument's type and handled SETOF results the way
  `test/db/portablePostgres.ts` does; the file was then restored.
  `evals/results/2026-10-29-evals-typed-rpc.json`. So the pipeline behaves as
  the cases expect; the helper is what is broken. It is used by 9 test files,
  so fixing it is its own change.
- `evals/live.test.ts` **passed** (also with typed arguments), on
  `evals/fixtures/e8-confined-space-entry.md` (2.7 KB). `AI_MODEL` was left
  unset so the default Nebius models ran (the local `.env.local` picks a
  Cerebras model with no key). Only `ANTHROPIC_API_KEY` and `NEBIUS_API_KEY`
  went into the container. `evals/results/2026-10-29-live.json`.

| Live upload | Value |
|---|---|
| Whole run | 31.3 s |
| reconcile stage | 20.0 s (one extraction call 14.9 s, 4 entity duplicate reviews 4.7 s) |
| pages stage | 10.9 s (8 sections rebuilt) |
| AI calls | 31 |
| Tokens | 73,207 in, 6,768 out |
| Largest by tokens | section_lines 33,171 in; line_fact_check 19,430 in; editorial selection 9,099 in |

Even on a 2.7 KB file, review (fact checks and editorial selection) reads
about 40% of the input tokens, which matches the cost picture behind #42.
Caveat: the test prints the saved actions with `console.table`, and the table
was empty, so it only proves the upload did not fail.

## 4. PR #52 (#38): query instruction

**Verdict: it regresses. Do not merge as is.**

Method: PR #52's own change to `evals/retrieval/run.ts` plus its new
`lib/ai/queryText.ts` applied on top of main for the run, then removed. The eval
passes its own vector to `rankUnits`, so the PR's `rank.ts` edit does not affect
it, and main's later `rank.ts` change (`searchMode`) does not either because
the eval sets the mode itself. Files: `evals/retrieval/results/2026-10-29-pr52-*.json`.

| Variant | Measure | main | PR #52 | Change |
|---|---|---|---|---|
| legacy | hit@5 | 90.0% | 85.0% | -5.0 points |
| legacy | hit@10 | 96.7% | 91.7% | -5.0 points |
| legacy | MRR | 0.804 | 0.722 | -0.082 |
| legacy | scoped MRR | 0.775 | 0.530 | -0.245 |
| hybrid | hit@5 | 58.3% | 58.3% | 0 |
| hybrid | hit@10 | 75.0% | 78.3% | +3.3 points |
| hybrid | MRR | 0.488 | 0.478 | -0.010 |
| hybrid + rerank | hit@5 / hit@10 / MRR | 100% / 100% / 0.908 | 100% / 100% / 0.908 | 0 |

22 of 60 legacy questions change rank; most move down (q24 from 1 to 10, q43
from 1 to 8, q37 from 7 to 12). Production runs hybrid + rerank since #43's env
vars were set, and there the instruction makes no difference. Legacy is still
the path whenever the reranker is not configured (`searchMode` in
`lib/chatbot/rank.ts`), and there it is worse. So the PR adds risk and no gain. If it is
tried again, retune `MIN_SIMILARITY` (0.35) and the glossary `p_min` (0.3) as
the PR suggests, or try a shorter instruction, and rerun this eval.
